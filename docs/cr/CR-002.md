## 需求原文（逐字记录，未脑补）

> 看看，都什么需要补充修改的，比如set其实也要有lua插件的修改，不能只改git。del也是要回撤就都回撤。
> 现在做成两部分，一部分还是原来的 Git 管理，另一部分是插件的管理。
> 关于插件的版本设置，只需要提供一个 set 函数，直接把所有的操作都汇总成这个函数。
> 具体的设计思路如下：1. 接口封装：插件系统只对外提供这一个函数，用于指定把当前项目设置成什么版本，具体怎么操作由插件系统内部处理。
> 2. 参数扩展：可以再增加一个参数，用于指定支持的"项目结构"或"框架"，然后把该框架设置成对应的版本。
> 3. 核心要求：一定要支持一个语义化的函数，用于把当前项目设置成指定版本，所有版本管理全在 Git tag 中去做。
> 4. 屏蔽细节：对于所有插件支持的内容，只需要去设置版本，不需要知道内部具体是怎么实现的。
> （现象）PATH 中旧版 `git-tags.exe -h` 缺少 check/sync/set/plugins。

## 现状核对结论（探索确认，非脑补）

- `engine.Set` 已遍历所有激活 provider（含 Lua 插件）写回 + 可选建 tag —— "set 联动插件改文件"**已满足**（旧版二进制误导判断）
- provider 契约 `write(project, version)` 即统一语义 set（设计点 1/3/4 基本是现状）
- 真 gap：① `del` 只删 tag 不回滚文件；② `set` 无框架定向参数；③ CLI 帮助无分组；④ PATH 旧版二进制
