## 需求原文（逐字记录，未脑补）

> 添加go项目的支持
> 添加go项目的lua支持
> 不需要这些 "internal/provider" ，应该是只用 plugins 中的 lua 来进行

## 决策

| 决策项 | 结论 |
|--------|------|
| provider 实现机制 | **单轨 Lua**：退役 `internal/provider` 中 tauri/flutter/uv/node 的 Go 实现（含 fileProvider 骨架、JSON/TOML helper、单测与 testdata），保留 Provider 抽象与 GitProvider（权威源，平台职责） |
| provider 注册 | `newEngine` 不再注册 Go 内置；provider 只来自 Lua（内嵌插件 → 用户插件逐级覆盖），git 由引擎固定作为权威源 |
| go 项目版本载体 | go.mod 无版本字段，插件按常见约定依序探测：根目录 `VERSION` 文件 → 根目录 `version.go` 的 `Version = "x"`（var/const、大小写均可）→ `internal/version/version.go`；均不存在则插件不激活（仅 git tag） |
| go.lua 注册 | 内嵌进二进制（`plugins/go.lua` + main.go 注册），priority 60 |

## 影响评估

| 项 | 值 |
|----|-----|
| 是否改库 | 否 |
| 是否重构 | 是 —— 删除 internal/provider 中 4 个 Go 项目类型实现（~400 行）与其单测/testdata |
| 是否影响旧功能 | 运行时 provider 一直是内嵌 Lua（Go 版为被覆盖兜底），删除兜底后行为不变；新增 go provider |
